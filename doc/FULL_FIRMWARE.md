# Full firmware image

`tools/pack_firmware.py` merges every flash section into one 16 MB image that
can be written to offset `0x0` in a single operation. It replaces the previous
multi-step install (app flash, partition table, then `parttool.py` for fonts).

| Offset     | Size    | Contents                            | Source                                    |
| ---------- | ------- | ----------------------------------- | ----------------------------------------- |
| `0x000000` | 23,568  | bootloader                          | `build/bootloader/bootloader.bin`         |
| `0x008000` | 3,072   | partition table                     | `build/partition_table/partition-table.bin` |
| `0x010000` | app     | factory app                         | `build/fake_pod_nano_remix.bin`           |
| `0x410000` | 8 MiB   | font partition (raw FONT image)     | `font_data/font_partition.bin`            |
| `0xC30000` | 3,904 KiB | littlefs, formatted and empty     | generated by the script                   |

Everything else (NVS, `phy_init`, coredump and the gaps) is `0xFF`.

## Build

```powershell
idf.py build
python tools\pack_firmware.py
```

The packer reads the offsets from `partitions.csv` and
`build/flasher_args.json`, verifies that every section fits its partition,
fills gaps with `0xFF`, re-reads the written file and checks each section's
hash. The result is:

- `build/fake_pod_nano_remix_full_16mb.bin` — the merged 16 MB image
- `build/fake_pod_nano_remix_full_16mb.json` — offsets, sizes, MD5/SHA-256

Use `--output PATH` for a different target and `--flash-size BYTES` for a
different flash size.

## Empty littlefs partition

The littlefs partition is not left erased: it contains a real filesystem
formatted by the system `littlefs` Python package (`pip install
littlefs-python`) with no files in it. The geometry matches
`components/joltwallet__littlefs`, so the firmware mounts it directly instead
of hitting `format_if_mount_failed`:

- block size 4096 (esp_littlefs hardcodes `CONFIG_LITTLEFS_BLOCK_SIZE 4096`)
- 976 blocks (`0x3D0000 / 4096`), exactly the partition size
- on-disk version `0x00020001` (littlefs 2.1), the same `LFS_DISK_VERSION` as
  the bundled littlefs 2.11 sources
- no entries; `pod_storage_init()` creates `/littlefs/user_data` on first boot

## Flash

```powershell
esptool --chip esp32s3 -p COM9 write_flash 0x0 build\fake_pod_nano_remix_full_16mb.bin
```

A full-image write replaces NVS as well (it is `0xFF` padding), so stored
settings and Wi-Fi calibration are reset; the chip re-initialises `phy_init`
and NVS on the next boot.
